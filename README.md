# Виджет Xiaomi LYWSD03MMC для Windows

Отдельная карточка на рабочем столе: температура и влажность. Тёмное оформление
в стиле Windows 11 / Fluent, голубой акцент, тонкая рамка и скруглённые углы.
Перетаскивание мышью. Это не расширение
панели Windows «Виджеты». Нужны Windows 10/11, Python и Bluetooth Low Energy.
Виджет рассчитан на штатную BLE-прошивку LYWSD03MMC; доступ к измерениям зависит
от версии прошивки. Он не перепрошивает датчик и не использует облако Xiaomi.

## Первый запуск

Запустите `install.cmd`, затем `start_widget.cmd`. Установщик создаёт окружение
`.venv` внутри проекта, не меняя глобальные зависимости Python.

Либо откройте PowerShell:

```powershell
cd S:\any\mi-temperature-sensor
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe widget.py
```

После установки запускайте `start_widget.cmd` двойным щелчком. Он открывает
виджет через `pythonw` без постоянного окна консоли. Также можно запускать
`widget.pyw`, если расширение `.pyw` связано с нужным Python в Windows.

Не запускайте `sensor.py` одновременно с виджетом: оба пытаются подключиться
к датчику. Закройте Mi Home на телефоне на время подключения. Первое обнаружение
может занять до 30 секунд; установление соединения может занять ещё до 30 секунд.
Второй экземпляр виджета не запускается, чтобы избежать конкурирующих подключений.

## Управление

- Перетаскивайте карточку левой кнопкой мыши.
- Потяните за любой край или угол, чтобы изменить размер. Курсор меняется на
  стрелку изменения размера; текст и значки масштабируются без искажения пропорций.
  Ширина и высота меняются вместе: карточка всегда квадратная (1:1).
  Минимальный размер — 224 × 224, исходный — 336 × 336, максимальный — 400 × 400.
  При растягивании угла противоположный угол остаётся на месте; при растягивании
  края вторая сторона меняется симметрично относительно центра.
  Сохранённый прямоугольный размер приводится к квадрату при запуске, а слишком
  большой размер автоматически ограничивается.
- Правая кнопка: настройки, переподключение и закрытие. Пункты открытия журнала,
  истории батарейки и режим «Поверх всех окон» убраны. Обычные приложения могут
  закрывать карточку; это не прикрепление к слою рабочего стола за значками.
- В настройках меняются название и Bluetooth-адрес. Пустой адрес включает
  поиск. Адрес первого успешно подключённого датчика запоминается.
- Окно настроек оформлено в стиле Fluent: шестерёнка в заголовке, поля на всю
  ширину и кнопки «Сохранить» / «Отмена». Размер содержимого — 300 × 400.
  Технические пояснения и диагностика
  в этом окне не отображаются. «Отмена» не меняет настройки.
- Там же выбираются постоянная связь с запросом экономии или редкие измерения
  с отключением после получения данных. Интервал редкого чтения — 5–60 минут.
  Выбор режима — компактный тёмный список с двумя вариантами, без стрелок прокрутки.
- Если датчиков несколько, найденные адреса доступны в журнале. Откройте
  настройки и укажите нужный в поле адреса.
- Положение, размер, название и адрес сохраняются через Windows QSettings
  в `HKEY_CURRENT_USER\Software\MiTemperatureSensor\DesktopWidget`.
  Там же сохраняются режим и интервал чтения.
- «Обновлено» и «Следующее чтение» скрыты с карточки. Возраст последнего
  измерения доступен только во всплывающей подсказке; отсчёт не показывается.
- На минимальном размере название и подписи не уменьшаются до мелкого шрифта:
  для них предусмотрен нижний предел размера. Отступы между шапкой, температурой
  и блоком влажности одинаковые и рассчитываются по реальным размерам текста.
- При потере соединения виджет сохраняет последние значения, показывает статус
  и пытается подключиться снова. В постоянном режиме через 2 минуты значения
  становятся приглушёнными. В редком режиме учитываются интервал и запас 45 секунд.
- Напряжение батарейки отображается небольшим приглушённым текстом внизу справа,
  например `2,912 В`, рядом с контурной иконкой. Пока измерений нет, оно скрыто.
- Подсказка при наведении содержит не больше трёх коротких строк: статус,
  напряжение и возраст измерения. Технические подробности в ней не показываются.
  Напряжение не выдаётся за точный процент заряда; контур батарейки не изображает
  выдуманный уровень заряда.

Проверка внешнего вида без датчика:

```powershell
.\.venv\Scripts\python.exe widget.py --demo
```

Демо не подключается к Bluetooth, показывает тестовые значения и помечено
«Демонстрация». После двух минут его показания также считаются устаревшими.

## Если данных нет

Проверьте Bluetooth, батарейку, расстояние и подключение другого приложения.
Статус «Сопряжено» в Windows сам по себе не означает получение показаний.
Краткий статус доступен во всплывающей подсказке карточки. Подробности записываются в журнал:
`%LOCALAPPDATA%\MiTemperatureSensor\widget.log`. Журнал содержит адрес датчика.
Если в нём указана отсутствующая характеристика измерений, текущая прошивка
потребует другого способа чтения. Перепрошивка автоматически не выполняется.

Компьютер должен работать и не спать. Этот виджет показывает текущие показания,
но не ведёт историю температуры/влажности и не восстанавливает пропуски после сна.

### Повторное подключение

После успешного подключения найденный объект BLEDevice запоминается **в памяти**.
Плановые чтения и ручное «Переподключиться» используют его напрямую: каждый раз
ждать нового рекламного пакета не требуется. Между чтениями соединение по-прежнему
закрыто; этот кэш не держит Bluetooth-соединение и не изменяет интервал 5 минут.
При ошибке подключения или отсутствии измерений кэш сбрасывается, и следующая
попытка снова ищет датчик. Первичный поиск увеличен с 10 до 30 секунд, чтобы
редкие рекламные пакеты не приводили к преждевременному «Нет связи».
После перезапуска программы требуется новое обнаружение.

Если датчик действительно недоступен, сообщение об ошибке остаётся: кэш не
устраняет слабый сигнал, разряженную батарейку или подключение другого приложения.
Проверьте расстояние и закройте Mi Home / `sensor.py`.

## Оптимизация батарейки

Реализация основана на [issue #32](https://github.com/JsBergbau/MiTemperature2/issues/32)
и решении высокого расхода в [issue #18](https://github.com/JsBergbau/MiTemperature2/issues/18#issuecomment-590986874).
Основные выводы: при слабой связи повторные передачи и частые подключения могут
повышать расход; отключение уведомлений или более редкая перерисовка окна сами
по себе не устраняют расход поддержания BLE-соединения. RSSI недостаточно для
надёжного определения тока. Плановое переподключение здорового соединения не
выполняется: оно тоже стоит энергии.

### Постоянная связь (необязательно)

При каждом подключении, после подписки на измерения, отправляется известная
команда штатной прошивки `f4 01 00` в характеристику
`ebe0ccd8-7a0a-4b0c-8a1a-6ff2997da3a6`. Это запрос изменения параметров связи,
который в обсуждении позволил снизить расход при постоянном соединении.
Используется UUID, а не старый фиксированный handle `0x0046`. Запись выполняется
с подтверждением GATT и тайм-аутом 10 секунд. После неё виджет не выполняет
дополнительных GATT-чтений/записей: некоторые прошивки при этом обрывают связь.

**Подтверждение записи GATT не доказывает применение интервала Bluetooth**:
Windows/адаптер могут не принять запрос датчика. Виджет не измеряет ток и не
обещает конкретный срок работы батарейки. При отсутствии характеристики или
ошибке отправки команды постоянное соединение не удерживается: получается
одно измерение, соединение закрывается и следующий сеанс выполняется после
паузы 5 минут (либо выбранного интервала). Ошибка видна в диагностике.
После запроса экономии ожидание первого измерения ограничено 30 секундами;
затем соединение закрывается, и применяется задержка повторных попыток.
После начала передачи отсутствие новых данных в течение 2 минут также
приводит к закрытию соединения и увеличивающейся паузе.
Консольный `sensor.py` тоже отправляет запрос; при его недоступности считывает
одно измерение и завершается, а не держит потенциально прожорливую связь.

### Редкие измерения (по умолчанию — каждые 5 минут)

Правая кнопка → **Настройки → Режим чтения → Обновление по интервалу**.
После получения измерения виджет отключается и ждёт 5–60 минут перед следующим
сеансом. Это именно пауза между сеансами, а не изменение частоты измерений в
самом датчике. Во время паузы карточка просто сохраняет последние показания,
без надписей «Обновлено» и «Следующее чтение». Проверка устаревания остаётся
активной: при задержке данных значения приглушаются и появляется предупреждение.
Частые подключения могут свести
экономию на нет; этот режим полезен, если достаточно редких показаний, но его
выигрыш по сравнению со стабильной экономичной связью нужно проверять.

### Обрывы и наблюдение

После неудачных циклов пауза растёт: **15, 30, 60, 120, 240, 300 секунд**,
затем остаётся 300 секунд. Одно полученное измерение на коротком соединении
не сбрасывает задержку. Сброс происходит после сеанса с данными длительностью
не менее 2 минут или успешного планового редкого чтения.
Диагностика содержит число попыток и неожиданных обрывов за последние 15 минут.
При повторных сбоях карточка предлагает проверить сигнал; приблизьте датчик
или USB-адаптер, попробуйте изменить их расположение.

Для длительного наблюдения сохраняется не чаще одного раза в час на датчик
файл `%LOCALAPPDATA%\MiTemperatureSensor\battery.csv` с временем UTC, адресом
и напряжением. При необходимости файл можно открыть через Проводник. Интервал записи
сохраняется при перезапуске благодаря чтению CSV. Деморежим файл не заполняет.
Напряжение может колебаться от нагрузки и температуры: отдельное падение не
доказывает ускоренный разряд, а линейный перевод напряжения в проценты не используется.

Более радикальный вариант из поздних комментариев #32 — получать только
BLE-рекламу без подключения (например, с pvvx/ATC-прошивкой). Здесь он **не
реализован**: открытый формат требует другой прошивки, а штатные шифрованные
пакеты — bindkey и декодер. Виджет ничего не перепрошивает и не извлекает ключи.

## Автозапуск (необязательно)

Нажмите Win+R, введите `shell:startup` и добавьте туда **ярлык** на
`start_widget.cmd`. Автозапуск не включается автоматически.

## Сборка EXE (необязательно)

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --onefile --windowed --add-data "assets;assets" --name MiTemperatureWidget widget.py
```

Файл появится в `dist\MiTemperatureWidget.exe`. Для его запуска отдельный Python
уже не нужен. Сборка может быть крупной из-за графической библиотеки Qt.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
